# ТЗ: Telegram-бот для публикации новостей с сайтов

## 1. Цель

Бот периодически читает списки новостей на сайтах (первый источник — freiberg.de), переводит анонсы с немецкого на русский через DeepL и автоматически публикует их в несколько Telegram-каналов и чатов сообществ.

## 2. Принятые допущения

Эти решения приняты по умолчанию. Их можно поменять до начала разработки.

- В пост идут только данные из списка новостей: заголовок, подзаголовок (если есть) и анонс. Полный текст статьи бот не загружает.
- Картинок и хештегов в постах нет.
- Интерфейс бота и сообщения админу на русском.
- Если перевод недоступен (закончилась квота DeepL, ошибка API), новость **не публикуется** на немецком. Она остаётся в очереди, админ получает уведомление.
- Получателей админ добавляет и удаляет командами бота, список хранится в БД.
- Админы задаются списком Telegram user ID в `.env`.

## 3. Источники

### 3.1 Архитектура

- Каждый источник реализуется отдельным классом-парсером с общим интерфейсом, например `fetch() -> list[NewsItem]`.
- Новый источник добавляется так: новый класс плюс запись в таблице `sources`. Ядро бота при этом не меняется.
- На старте подключён один источник: `freiberg_neuigkeiten`.

### 3.2 Источник freiberg.de (Neuigkeiten)

- **URL:** `https://www.freiberg.de/stadt-und-buerger/aktuelles/neuigkeiten`.
- **RSS нет.** Сайт на TYPO3, стандартный `?type=9818` отдаёт HTML. Поэтому парсим HTML.
- **Объём.** Парсим только первую страницу списка (около 10 последних новостей).
- **Поля элемента списка:**
  - **URL статьи.** Абсолютная ссылка вида `/stadt-und-buerger/aktuelles/neuigkeiten/<slug>`. Это уникальный ключ новости.
  - **Заголовок.** Брать из атрибута `title` ссылки. Видимый текст ссылки может содержать мусор: подписи к фото (например, `Adobe Stock`), дату, метку.
  - **Дата.** Формат `ДД.ММ.ГГГГ`, стоит перед заголовком.
  - **Метка.** Например, `Pressemitteilung`. Может отсутствовать. Сохраняем, но не публикуем.
  - **Подзаголовок.** Выделенный жирным текст после заголовка. Может отсутствовать.
  - **Анонс.** Текст после заголовка и подзаголовка. Обрезан сайтом и заканчивается на `…`. Хвост `mehr erfahren` удалить, многоточие оставить.
- **Тестовые данные.** Сохранить реальную HTML-страницу в `tests/fixtures/` и написать тесты парсера на ней.
- **Вежливость.** Указывать понятный `User-Agent` с контактом. Делать один запрос на опрос, без параллельных запросов.

## 4. Перевод (DeepL)

- Использовать официальную Python-библиотеку `deepl` и бесплатный API-ключ.
- Направление перевода: `source_lang=DE`, `target_lang=RU`.
- Что переводим:
  - заголовок;
  - подзаголовок и анонс, объединённые в один текст.
- Перевод сохраняется в БД. Повторно одна и та же новость не переводится.
- Глоссарий местных терминов (Silberstadt, Stadtrat, Amtsverweser, Kornhaus и т. п.):
  - если DeepL поддерживает глоссарии для пары DE→RU, использовать их;
  - иначе делать пост-замену по словарю из конфигурационного файла `glossary.yaml`.
- Ошибки:
  - **Квота исчерпана (HTTP 456).** Новости остаются в статусе `pending_translation`. Админ получает уведомление не чаще 1 раза в сутки.
  - **Временные ошибки (429, 5xx, сетевые).** Повторить попытку с экспоненциальной задержкой. Если не удалось, повторить на следующем цикле опроса.

## 5. Формат поста

Используется parse mode HTML. Все вставляемые строки экранируются.

```
<b>{заголовок_ru}</b>
<i>{заголовок_de}</i>

{текст_ru}

<a href="{url}">Читать оригинал</a>
```

- Превью ссылки отключено, чтобы не дублировать контент.
- Пост целиком укладывается в лимит 4096 символов. Анонсы короткие, но защиту от превышения всё равно нужно сделать (обрезка текста с `…`).

## 6. Получатели

- Количество получателей не ограничено: каналы, группы, супергруппы.
- Для супергрупп с темами можно указать `message_thread_id`.
- Каждая новость отправляется всем активным получателям. Результат отправки каждому получателю фиксируется отдельно, чтобы при сбое не дублировать доставку тем, кто уже получил.
- Требования к правам:
  - в канале бот должен быть админом с правом публикации;
  - в группе бот должен быть участником с правом писать.
- Когда бота добавляют в чат или канал (обновление `my_chat_member`), бот присылает админу название и `chat_id`. Так админу удобно добавить этот чат в получатели.
- Ошибки отправки:
  - **403 (бот удалён, нет прав).** Получатель помечается неактивным, админ получает уведомление.
  - **429.** Соблюдать `retry_after`.
  - **Прочие ошибки.** Записать в лог, повторить на следующем цикле. Максимум 3 попытки, затем уведомить админа.
- Между отправками выдерживать паузу, чтобы не превысить ~20 сообщений в минуту в один чат.

## 7. Расписание

- Опрос источников раз в 30 минут (настраивается).
- **Тихие часы:** с 22:00 до 07:00 по Europe/Berlin (настраивается). Ночью автоматический опрос и публикация не выполняются. Кнопка «Опросить сейчас» опрашивает источники и ночью, но публикация всё равно ждёт утра.
- В 07:00 бот сразу выполняет цикл: опрос, перевод, публикация.
- Накопленные новости публикуются после 07:00 в хронологическом порядке, от старых к новым.
- Ограничение на пачку: в каждый чат не больше N постов подряд (по умолчанию 5), остальные уходят в следующих циклах.

## 8. Первый запуск источника

- Все новости, найденные на странице, помечаются как уже виденные (`skipped_initial`).
- Исключение: самая свежая новость (по дате, а при равных датах первая в списке) публикуется.

## 9. Мониторинг и уведомления админу

- **Нет новых новостей 7 дней** (настраивается) по какому-либо источнику:
  - отправить одно уведомление;
  - повторно уведомлять только после того, как появится новая новость и затем снова пройдут 7 дней тишины.
- **Парсер вернул 0 элементов 3 опроса подряд.** Это допущение: такая ситуация почти наверняка означает поломку вёрстки. Отправить немедленное уведомление.
- **Источник недоступен** (HTTP-ошибки) больше 24 часов: отправить уведомление.
- Ошибки перевода и доставки описаны в разделах 4 и 6.
- Все уведомления отправляются в личку всем админам из `.env`.

## 10. Админ-меню

Управление только через инлайн-меню в личке с ботом и только для пользователей из `ADMIN_IDS`. Меню открывается командой `/menu` (кнопка «Меню» в Telegram) или `/start`. Других текстовых команд нет; любое другое сообщение админа тоже открывает меню.

| Кнопка | Действие |
|---|---|
| Статус | Пауза или работа, время последнего опроса и последней новой новости по каждому источнику, очередь, остаток квоты DeepL |
| Пауза / Возобновить | Остановить или возобновить публикацию (опрос продолжается) |
| Источники | Список источников и их состояние, включение и выключение источника |
| Получатели | Список получателей, отключение и удаление. «Добавить по chat_id»: бот просит прислать `<chat_id> [thread_id]`, проверяет права и отправляет тестовое сообщение |
| Предпросмотр | Прислать в личку последнюю новость в формате поста, без публикации |
| Опросить сейчас | Внеочередной опрос источников |

## 11. Данные (SQLite)

Минимальная схема (детали на усмотрение разработчика):

- **`sources`:** `id`, `key`, `name`, `url`, `enabled`, `initialized`, `last_poll_at`, `last_new_item_at`, `consecutive_empty_polls`, `last_error_at`, `stale_notified`.
- **`news_items`:** `id`, `source_id`, `url` (unique), `published_date`, `label`, `title_de`, `subtitle_de`, `teaser_de`, `title_ru`, `text_ru`, `status` (`skipped_initial` / `pending_translation` / `ready` / `published` / `failed`), `created_at`.
- **`recipients`:** `id`, `chat_id`, `thread_id`, `title`, `active`, `added_at`.
- **`deliveries`:** `id`, `news_item_id`, `recipient_id`, `status`, `message_id`, `attempts`, `error`, `sent_at`. Ограничение уникальности на пару `(news_item_id, recipient_id)`.
- **`kv`:** глобальные флаги (`paused`, время последнего уведомления о квоте и т. п.).

Миграции делать простыми скриптами или через Alembic, если используется SQLAlchemy.

## 12. Стек и инфраструктура

- Python 3.12+.
- aiogram 3 для бота. Режим работы long polling, webhook не нужен.
- httpx для HTTP-запросов.
- selectolax или BeautifulSoup для парсинга.
- Официальная библиотека `deepl`.
- SQLite (aiosqlite или SQLAlchemy 2 async).
- APScheduler или фоновые задачи asyncio для расписания.
- pydantic-settings для конфигурации.
- Логирование: стандартный `logging` в stdout с уровнем из конфига.
- **Деплой:** AWS EC2 для публичных ботов, через Docker (Dockerfile и docker-compose). Файл БД лежит в volume.
- **`.env`:** `BOT_TOKEN`, `DEEPL_API_KEY`, `ADMIN_IDS`, `POLL_INTERVAL_MIN=30`, `QUIET_HOURS=22-7`, `TIMEZONE=Europe/Berlin`, `STALE_DAYS=7`, `DB_PATH`.
- Обязательно добавить `.env.example`, `README.md` (английский) и `README_RU.md` (русский) со ссылками на инструкции по запуску и деплою в `docs/`, `.gitignore`.

## 14. Критерии приёмки

1. Парсер на фикстуре извлекает все новости с правильными URL, датой, заголовком (без мусора), подзаголовком и анонсом (без `mehr erfahren`).
2. При первом запуске в каналы уходит ровно одна, самая свежая новость.
3. Новая новость появляется у всех активных получателей в течение одного цикла опроса (вне тихих часов). Пост соответствует формату из раздела 5.
4. Повторный запуск и перезапуск контейнера не приводят к дублям.
5. Ночью ничего не публикуется. После 07:00 накопленное уходит по порядку с соблюдением лимита на пачку.
6. Если удалить бота из одного чата, публикация в остальные продолжается, а админ получает уведомление.
7. Если DeepL недоступен, немецкий текст не публикуется, новость ждёт перевода, админ получает уведомление.
8. Уведомление «нет новостей 7 дней» приходит один раз и не повторяется до появления новой новости.
9. Админ-команды работают только для `ADMIN_IDS`.
10. Тесты проходят (`pytest`), проект запускается командой `docker compose up -d` по README.

## 16. Правила работы с репозиторием

- Не указывать Claude соавтором: не добавлять в коммиты строку `Co-Authored-By: Claude`, а в описания PR пометки вида «Generated with Claude Code».
- Сообщения коммитов писать на английском, кратко, в повелительном наклонении (например, `Add Freiberg news parser`).
- Один коммит — одна логическая часть работы (этап из плана).
